# 正式文章包结构说明

## 目的

每篇正式文章把正文、文章专属配图和最小资产说明放在同一个目录，避免出现“正文在分类目录、图片在另一个素材库”的双入口。资料来源、事实核验和发布记录仍在流程目录统一维护，既避免把核验入口塞进正文，也能保持可追溯性。

## 标准结构

```text
01-工具教程/
  12-MCP 是什么：AI 为什么需要一个 USB-C 接口/
    12-MCP 是什么：AI 为什么需要一个 USB-C 接口.md
    article.json
    assets/
      cover/                    # 可选；封面不在正文引用
      figures/                  # 正文图片只能从这里相对引用
      archive/                  # 本文章专属但不再用于正文的历史文件
07-资料与流程/
  历史素材归档/                  # 未入库、下架或无唯一文章归属的历史文件
  文章元数据/NN-中文标题.json
  文章资料核验台账.md
  文章资产登记表.md
  发布记录.md
```

## 放置规则

1. **正文与文章专属图**：放在单篇文章包；正文图用相对路径引用 `assets/figures/`。
2. **封面**：放在 `assets/cover/`（如有），只由 `article.json`、文章元数据和资产登记表登记；不在正文放封面链接。
3. **文章专属历史图**：放在同包 `assets/archive/`，保留文件和来源追溯，但不得被正文直接引用。
4. **无唯一文章归属的历史素材**：放在 `07-资料与流程/03-资产与核验/历史素材归档/`，作为历史证据而非正式文章素材来源。
5. **跨文章复用**：每篇正文只能引用自己的 `assets/figures/`；需要复用时复制经授权的文件到目标文章包、补足来源记录并在目标 `article.json` 登记，不能再建立顶层集中素材库。
6. **临时文件**：放在 `.tmp/`，完成检查后删除临时预览和生成脚本。

## 维护动作

- 新建或迁移文章包时，同步更新 `article.json`、文章元数据的 `article.path` 与 `assets.inline_images`、资产登记表正文路径及索引。
- 运行 `python 09-工具脚本/01-发布校验/图片资产检查.py`，确认正文图可打开、引用存在、位于文章包内且 `article.json` 已登记。
- 运行 `python 09-工具脚本/01-发布校验/一键发布检查.py`，确认文章编号、路径、README 与本地链接一致。

> 自 2026-08-07 起，顶层 `08-素材库/` 已移除，不作为当前或兼容的素材入口。
