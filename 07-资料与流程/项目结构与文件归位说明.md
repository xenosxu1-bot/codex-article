# 项目结构与文件归位说明

本说明用于维护仓库目录边界。正式文章、素材、流程记录和外部证据各自只有一个长期位置；临时文件不能替代正式资料。

## 顶层目录职责

| 位置 | 放什么 |
| --- | --- |
| `00-知识库导航/` | 面向读者的首页、阅读路径，以及分类、系列、标签和总索引。 |
| `01-工具教程/` 至 `06-热点追踪/` | 已入库的正式文章。正文只按一个主分类存放，交叉关系通过索引和标签维护。 |
| `07-资料与流程/` | 写作规范、选题与发布记录、文章元数据、去重报告和维护说明。 |
| `08-素材库/` | 被正式文章引用的封面、正文插图、官方截图、底图和已登记归档素材。 |
| `09-工具脚本/` | 项目适配配置、索引重建、质量检查和归档工具入口；通用视觉生产规则与生成器以锁定版本的 `article-Skill` 为准。 |
| `10-外部原文归档/` | 外部原文的原始快照、自动转换文本和去重参照，不占用正式文章编号。 |
| `.tmp/`、`.work/` | Git 忽略的任务工作区，仅存放候选图、预览、诊断和短期脚本。 |

仓库根目录只保留入口文件和上述一级目录。Git 操作只在 `D:\projects_git\Codex_article` 执行，不创建嵌套仓库、发布副本或平行文章目录。

## 二级目录归位

### 流程与记录

- `07-资料与流程/文章元数据/`：标准稿和深度稿的单篇 JSON 元数据。
- `07-资料与流程/选题草稿/`：尚未入库的 Brief、草稿和选题工作材料。
- `07-资料与流程/内容去重报告/`：候选文章与历史内容的查重结果。
- `07-资料与流程/历史脚本与模板/`：不再作为当前执行入口、但需要追溯的旧脚本和模板。

### 图片与素材

- `08-素材库/图片/文章封面/`：正式文章封面。
- `08-素材库/图片/正文插图/`：正式文章引用的正文信息图或说明图。
- `08-素材库/图片/官方工具截图/`：经核验的官方界面或产品截图。
- `08-素材库/图片/封面底图/`：两阶段封面生产中已登记的无文字视觉底图。
- `08-素材库/图片/归档/`：不再被正式文章引用、但需保留追溯记录的图片。

### 外部原文证据

每篇外部文章放入 `10-外部原文归档/EXT-日期-序号-标题/`。其中 `source.html` 保留原始快照，派生的 `content.md` 和 `content.txt` 只能由原始 HTML 转换；它们不是正式文章正文。

## 新文件如何选择位置

1. 新增正式文章：先确定主分类，写入 `01-工具教程/` 至 `06-热点追踪/` 中的对应目录，并同步索引和登记表。
2. Brief、选题状态、发布记录、元数据或查重结果：写入 `07-资料与流程/` 的对应记录目录。
3. 已确认会被文章引用的封面、插图或官方截图：写入 `08-素材库/` 的对应图片区。
4. 外部原文及其自动转换文本：写入 `10-外部原文归档/`，并保留来源与权利说明。
5. 可复用的项目检查、索引或归档工具：写入 `09-工具脚本/`；不要在项目内复制独立的视觉生产规则或图像生成器。
6. 候选图、裁切预览、诊断输出和一次性辅助脚本：先放在 `.tmp/` 或 `.work/`。任务结束后，确认没有正式引用或待审用途，再按清理规则处理。

目录调整前，先检查现有引用、登记表和 Git 状态。没有明确迁移映射时，不通过移动文件来改变文章编号、资产路径或来源证据的位置。
