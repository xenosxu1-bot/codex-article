11. AI Agent 到底是什么：从聊天机器人到自动完成工作的系统

> 你让 AI 整理一份资料，十分钟后它给了你一篇看似完整的总结。可当你问“这句话来自哪一页”“它有没有动过原文件”，屏幕突然安静了。真正让人不放心的，从来不是它会不会回答，而是出了岔子以后，你能不能查清、叫停、收回。

AI Agent 值得学，不是因为它听起来更厉害，而是因为它把 AI 从“陪你聊天”往“替你推进一件小事”推了一步。对第一次接触的人，先记住一句就够了：**Agent 不是自动替你负责的人；它是一个需要你划边界、看过程、验结果的执行助手。**

![AI Agent 从目标到可验收交付](assets/figures/11-AI Agent 到底是什么：从聊天机器人到自动完成工作的系统-正文插图01.png)

> **可以转发的一句话：Agent 的分水岭，不是会不会调用工具，而是能否在边界内交付可验收结果。**

## 一、先用一个真实场景理解：它到底替你多做了什么

假设你要把一个项目的会议记录整理成待办清单。

- **普通聊天**：你复制会议记录，AI 给你一份待办；遗漏谁负责、哪件事没有日期，还得你自己再追问。
- **固定自动化**：每次都把表单里的“负责人、截止时间、事项”搬进表格；规则清楚时很稳，遇到模糊表达就容易卡住。
- **Agent**：在你允许的范围内读取会议记录，提取待办，标出没有负责人或日期的项目，写入一份草稿表，最后把“已完成、待确认、没有找到”的部分一起交给你。

它的价值不在于“替你少打几行字”，而在于减少你在**找资料、重复交代、整理中间结果、检查遗漏**之间来回切换。但它不能替你判断谁该负责，也不该在没有确认时把任务发给同事。

## 二、Agent 由什么组成：模型只是其中一块

官方的 Agent 开发资料通常会把系统拆成指令、上下文、工具、交接、护栏和追踪等部分。给新手翻译一下，就是下面这五件事：

1. **目标**：你到底要它交什么，例如“一份待办草稿”，而不是“帮我处理一下”。
2. **上下文**：它允许看哪些文件、规则和历史信息。
3. **工具**：它能不能搜索、读文件、写表格、运行命令或调用业务系统。
4. **边界**：哪些动作必须停下来问你，例如发送邮件、删除文件、改权限、联网查询。
5. **证据**：它最后是否交代了读了什么、改了什么、跑了什么检查、哪里仍不确定。

模型负责理解和生成；真正让 Agent 能推进任务的，是后面四项。少了它们，再会说话的模型也更像聊天助手。

## 三、第一次别追求“全自动”：做一个 15 分钟只读实验

选一个**可恢复、低风险、没有隐私**的资料夹。可以放三份公开会议纪要、几篇自己写的 Markdown 笔记，或一个练习代码仓库。不要用客户资料、生产代码、真实密钥、病历或财务文件。

把下面这张任务卡原样交给你正在使用的 Agent 产品；不同产品的按钮和界面不同，但这张卡的判断逻辑不变：

```text
任务：把当前资料夹整理成一页待办摘要。

允许读取：仅当前资料夹。
禁止动作：不联网、不修改原文件、不发送消息、不创建外部账号。
输出：生成一份 Markdown 草稿，分为“已明确待办 / 待确认信息 / 原文没有说明”。
证据：每条待办附文件名或段落标题。
停止条件：发现资料冲突、读不到文件，或需要写入原文件时，先停下来说明原因。
```

**成功信号**：它没有越过资料夹；能列出依据；不知道时会写“原文没有说明”。
**失败信号**：一上来就改文件；把猜测写成事实；没有来源也不承认缺失。
失败时先检查任务范围是否写清、工具是否被赋予写入权限、资料本身是否完整；不要急着换模型。

## 四、你真正要学的是“交代任务”，不是背术语

很多人第一次用 Agent，会写：“帮我把项目整理好。”这句话太大，谁都验不了。换成下面的写法，结果会立刻可控：

> 只读取 `docs/` 和 `src/`。先画出项目入口和主要模块，再列出最近一次变更可能影响的 5 个位置。每个结论附文件路径；无法确认就标记“待核验”。不要修改文件、不要联网。最后输出 Markdown 报告；如果需要运行命令，先列出命令等我确认。

这段话有五个新手最该保留的字段：**范围、动作、禁止项、交付物、停止条件**。以后无论你用哪款 Agent，先补齐这五项，比把提示词写得“高级”有用得多。

**图 2｜不是谁更高级，而是交付责任不同：输出文字、执行固定规则，还是在边界内推进任务。**

## 五、哪些事适合先交，哪些事必须留给人

先交给 Agent 的，最好同时满足：**可检查、可回滚、出错影响小**。

| 可以从这里开始 | 先不要交给它 |
| --- | --- |
| 把公开资料整理成带来源的初稿 | 直接修改生产系统、批量删除数据 |
| 扫描练习仓库，画模块地图 | 代替你做医疗、法律、金融判断 |
| 运行已有测试，汇总失败项 | 用你的身份向客户承诺或发送不可撤回消息 |
| 把会议记录变成待办草稿 | 变更权限、密钥、支付或发布设置 |

一条朴素的底线：**只读可以放宽，草稿可以委托，修改要限范围；发布、发送、删除和权限变更必须由人确认。**

## 六、用四个问题验收，而不是看它说得像不像

一次任务结束后，别只问“结果好不好”。按顺序问：

1. **它读了什么？** 有没有列出文件、来源、使用范围？
2. **它做了什么？** 有没有列出实际工具动作、变更文件或执行命令？
3. **它没做什么？** 有没有承认资料缺失、权限不足或未解决项？
4. **我能不能接手？** 输出是否能复核、修改是否能回滚、下一步责任人是否清楚？

如果四个问题里有两个答不上来，这次不要扩大权限。先把失败写进任务卡，再用同一个低风险任务重试一次。

## 七、今天的终点：留下一个能复用的小闭环

今天不必搭多 Agent，不必接公司系统，也不必追求它替你全天工作。你只需要留下三样东西：一个低风险资料夹、一张任务卡、一份包含“成功”和“资料里没有答案”的结果。

下次再用 Agent 时，把任务卡复制出来，换掉资料范围和交付物。你会慢慢发现：真正稳定的不是某个模型的神发挥，而是你能否让每次任务都**先说清楚、再小步执行、最后留下证据**。
