# 公众号视觉设计系统 v2.0

## 目标

把公众号封面和正文插图从“临时拼图”升级为“模板化视觉产品”。任何图片必须先服务正文问题，再符合统一排版和移动端可读性。

## 基础 token

| 项 | 默认值 |
| --- | --- |
| 正文图画布 | 1600 × 900 |
| 封面画布 | 2350 × 1000 |
| 正文图安全区 | 四边不少于 64 px，文字区不少于 80 px |
| 字体 | 微软雅黑 / 思源黑体；标题加粗，正文常规或半粗 |
| 正文图主标题 | 44-52 px |
| 卡片标题 | 22-28 px，≤ 6 个汉字 |
| 卡片说明 | 20-25 px，短词化，不超过 2 行 |
| 圆角 | 18-32 px，单图内保持一致 |
| 阴影 | 轻阴影；不能制造脏边或压低文字对比 |
| 背景 | 浅色科技底或深色科技底；同篇保持一致 |

## 模板库

- inline_1600x900_layer_stack：一侧主视觉 + 一侧 4-6 层卡片。适合“结构、层级、系统”。
- inline_1600x900_step_flow：横向或环形步骤，3-6 步。适合“操作流程”。
- inline_1600x900_compare_cards：左右两组卡片，适合“旧做法 vs 新做法”。
- inline_1600x900_checklist_grid：2×2、2×3 或 3×2 检查卡，适合“清单、避坑”。
- inline_1600x900_hub_spoke：中心概念 + 外围要点，适合“概念图”。

## 必须预览

- 100% 原图：检查裁切、碰撞、对齐、边距、字重和层级。
- 50% 缩略图：检查是否还有主要信息。
- 375px 手机宽：检查主标题、卡片标题和关键短词是否可读。
- 文章上下文：图前有“为什么看这张图”，图后有“看完怎么做”。

## 重做规则

只要出现文字挤压、遮挡、乱码、风格漂移、卡片不齐、连线穿字、底部条压住内容，直接回到 visual_spec 重做。不得在同一失败构图上反复补丁式修改。
