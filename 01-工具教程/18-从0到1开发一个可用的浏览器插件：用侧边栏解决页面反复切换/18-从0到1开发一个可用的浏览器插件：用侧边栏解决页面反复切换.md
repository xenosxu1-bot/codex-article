18. 从 0 到 1 开发一个可用的浏览器插件：用侧边栏解决页面反复切换

每天打开浏览器，最浪费时间的往往不是做事，而是找入口：项目主页在一个收藏夹，文档在另一个窗口，本地资料又藏在文件夹里。浏览器重启后，还要重新确认“刚才那个页面到底在哪里”。

这篇文章不做复杂的在线工作台，只做一个轻量侧边栏插件：让当前页面、已打开页面、搜索、自定义入口和常用访问，都出现在网页旁边。

![从重复查找到侧边栏直达：插件 MVP 演进路径（原创流程图，非浏览器官方界面）](assets/figures/18-从0到1开发一个可用的浏览器插件：用侧边栏解决页面反复切换-正文插图01.png)

## 一、先把目标缩小到一个可验证闭环

第一版只需要回答四个问题：

- 侧边栏能不能打开？
- 能不能看到当前页面？
- 能不能切换到已经打开的页面？
- 能不能保存几个自己的入口？

暂时不做在线同步，也不读取完整浏览历史。先让插件完成这条路径：

```text
打开侧边栏 → 搜索或点击入口 → 打开/切换页面 → 下次继续使用
```

这一步的价值在于，后面的每个功能都围绕“减少一次查找和切换”展开，而不是为了堆功能。

## 二、先让浏览器看到这个插件

新建文件夹，放入这些文件：

```text
sidebar-navigation-extension/
├── manifest.json
├── background.js
├── sidepanel.html
├── sidepanel.css
└── sidepanel.js
```

在 `manifest.json` 中声明插件身份和侧边栏入口：

```json
{
  "manifest_version": 3,
  "name": "侧边导航",
  "version": "0.1.0",
  "permissions": ["tabs", "bookmarks", "storage", "sidePanel"],
  "background": { "service_worker": "background.js" },
  "action": { "default_title": "打开侧边导航" },
  "side_panel": { "default_path": "sidepanel.html" }
}
```

`background.js` 只做一件事：点击扩展图标时打开侧边栏。

```js
chrome.runtime.onInstalled.addListener(() => {
  chrome.sidePanel.setPanelBehavior({
    openPanelOnActionClick: true
  });
});
```

打开 `edge://extensions/`，开启开发者模式，选择“加载已解压的扩展”，指向这个文件夹。

### 看到什么算成功？

点击扩展图标后，浏览器右侧出现侧边栏。此时还没有业务功能，但插件已经进入运行状态。

## 三、先展示当前页面

侧边栏第一块内容应该是用户正在看的页面，而不是一堆设置。

`sidepanel.html` 先放一个容器：

```html
<section class="section">
  <h2>当前页面</h2>
  <div id="currentPage"></div>
</section>
```

在 `sidepanel.js` 中读取当前标签页：

```js
async function loadCurrentPage() {
  const [tab] = await chrome.tabs.query({
    active: true,
    currentWindow: true
  });

  document.querySelector('#currentPage').innerHTML = `
    <button class="page-item">
      <strong>${tab.title || '未命名页面'}</strong>
      <small>${tab.url || ''}</small>
    </button>
  `;
}

loadCurrentPage();
```

### 效果

```text
当前页面
项目文档
https://example.com/docs
```

先不要急着做复杂卡片。页面标题、地址和一个打开动作，已经足够验证数据链路是否正常。

## 四、把已打开页面变成快速切换器

当前页面解决“我在哪里”，已打开页面解决“我刚才还在哪些页面”。

```js
const tabs = await chrome.tabs.query({
  currentWindow: true
});

const list = tabs.map(tab => `
  <button class="page-item" data-tab-id="${tab.id}">
    <strong>${tab.title || '未命名页面'}</strong>
    <small>${tab.url || ''}</small>
  </button>
`).join('');
```

点击时不重复创建标签页，而是切换到原来的页面：

```js
document.addEventListener('click', event => {
  const item = event.target.closest('[data-tab-id]');
  if (!item) return;

  chrome.tabs.update(Number(item.dataset.tabId), {
    active: true
  });
});
```

### 效果

```text
已打开页面
  项目主页
  项目文档
  数据看板
```

列表默认收起，用户需要时再展开。这样侧边栏不会持续遮挡网页内容。

## 五、加入搜索，而不是不断滚动列表

当入口变多后，搜索比分类更重要。搜索对象统一为：

- 当前页面；
- 已打开页面；
- 浏览器收藏夹；
- 自定义列表；
- 常用访问。

搜索框可以从最简单的字符串匹配开始：

```js
function match(item, keyword) {
  const text = `${item.title} ${item.url}`.toLowerCase();
  return text.includes(keyword.trim().toLowerCase());
}
```

输入关键词后重新渲染所有区域；没有结果时，告诉用户“换个关键词，或先添加自定义入口”。

## 六、接入收藏夹，但不要重做收藏夹

用户已有的浏览器收藏夹可以直接读取：

```js
const tree = await chrome.bookmarks.getTree();
```

渲染时保留原有文件夹层级，空文件夹不展示，文件夹默认收起。点击收藏页面时打开对应地址：

```js
chrome.tabs.create({ url: bookmark.url });
```

插件只负责“看得见、找得到、打开快”，不再复制一套复杂的收藏夹编辑能力。

## 七、增加自定义入口

收藏夹之外，用户还需要保存临时项目页面、本地资料和个人入口。先用一个简单对象表示：

```js
{
  id: "item-001",
  title: "项目文档",
  url: "https://example.com/docs",
  type: "web"
}
```

保存到浏览器本地：

```js
await chrome.storage.local.set({ customItems });
```

重新打开侧边栏时再读取：

```js
const result = await chrome.storage.local.get('customItems');
const customItems = result.customItems || [];
```

列表每行只保留一个主要打开区域，编辑、复制、删除和打开方式放进 `...` 菜单。标题和地址因此有更多展示空间。

网页和 `file:///` 地址可以交给浏览器打开；如果要调用系统默认程序打开本地文件或目录，则需要额外的本地助手或 Native Messaging，不放进第一版。

## 八、方案 A：做一个克制的常用访问

常用访问不读取完整浏览历史，只记录用户通过插件主动打开或切换的网页：

```js
{
  url,
  title,
  favIconUrl,
  openCount,
  lastOpenedAt
}
```

每次插件成功打开网页，就把访问次数加一。达到 2 次后进入候选列表，最多展示 5 条。`edge://`、`chrome://`、本地文件不参与统计；已经存在于自定义列表的页面也不重复显示。

![轻量常用访问：从插件主动打开到下次一键直达（原创流程图）](assets/figures/18-从0到1开发一个可用的浏览器插件：用侧边栏解决页面反复切换-正文插图03.png)

常用访问只提供四个动作：打开、加入自定义列表、复制地址、移除。自动化可以减少操作，但最终控制权仍然留给用户。

## 九、每完成一层，就在浏览器里验收

不要等所有功能写完再调试。推荐按这个顺序验证：

```text
加载插件
  ↓
打开侧边栏
  ↓
显示当前页面
  ↓
列出已打开页面
  ↓
点击后正确切换
  ↓
搜索能找到入口
  ↓
自定义列表重启后仍在
  ↓
重复访问后出现常用访问
```

![浏览器插件开发验收闭环：从加载到真正可使用（原创流程图）](assets/figures/18-从0到1开发一个可用的浏览器插件：用侧边栏解决页面反复切换-正文插图04.png)

如果侧边栏打不开，先检查 `manifest.json` 和扩展管理页；如果页面为空，检查 `sidepanel.js` 是否有语法错误；如果搜索无效，先确认数据是否已经加载，而不是先重写搜索逻辑。

## 十、用一个真实场景完成验收

最后不要只测试按钮。准备一个项目主页、一个项目文档、一个本地资料入口，再打开两个网页：

1. 通过侧边栏打开项目主页；
2. 在已打开页面中切换到项目文档；
3. 用搜索找到资料入口；
4. 重复打开项目文档两次；
5. 关闭浏览器后重新打开；
6. 检查自定义列表和常用访问是否还在。

如果这条路径顺利完成，插件就已经从“示例代码”变成了一个每天可以使用的小工具。

## 结语

浏览器插件不需要一开始就变成万能工作台。先解决一个明确问题：

> 让常用页面、已打开页面和自定义入口，在当前网页旁边随时可见、可搜、可打开。

完成最小闭环后，再考虑导入导出、手动置顶、分组管理或在线同步。好的插件不是把所有功能塞进侧边栏，而是让用户少一次查找、少一次切换、少一次重复操作。
