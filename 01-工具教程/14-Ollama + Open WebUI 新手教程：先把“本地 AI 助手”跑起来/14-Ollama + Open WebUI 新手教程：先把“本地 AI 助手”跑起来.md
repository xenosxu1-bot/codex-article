14. Ollama + Open WebUI 新手教程：先把“本地 AI 助手”跑起来

> 晚上十一点，你只是想问一句：冰箱里有鸡蛋、青菜和挂面，明早七点半要出门，怎么做一顿不手忙脚乱的早餐？可你又不太想把家里的行程、照片和聊天记录全交给一个陌生的云端窗口。

如果你也有过“明早就要出门，事情却还没理顺”的时刻，先别把本地 AI 当成一场部署考试。今晚只做一件小事：让电脑上的 AI 帮你把明天早晨安排得更清楚。

本文不承诺“完全离线”或“绝对隐私”，只带你跑通一个低风险闭环：**Ollama 负责在本机运行模型，Open WebUI 负责提供浏览器里的聊天入口。**

**今天做到这里就算成功：**终端能跑通一个本地模型；浏览器能打开一个只在本机访问的聊天入口；同一道“早餐任务”能给出事实、推断和待确认项。先完成这三步，再谈知识库或多人协作。

![Ollama 和 Open WebUI 的分工：Ollama 负责模型，Open WebUI 负责日常使用入口](assets/figures/14-Ollama + Open WebUI 新手教程：先把“本地 AI 助手”跑起来-正文插图01.png)

> **先记住：** 不必先搭一整套系统。它能把一件眼前的小事理顺，就已经值得继续。

## 第一部分｜先弄明白它是什么：本地 AI 助手能帮你什么

先不要把它理解成“更复杂的聊天软件”。这套组合把模型运行和网页操作分开：你可以先让本机模型说话，再决定是否需要更像聊天应用的网页界面。

Ollama 是本地模型运行工具：它帮助你下载、运行和管理模型，也提供本机 API。Open WebUI 是可自托管的网页界面：它让你在浏览器中选择模型、对话、保存记录，并可在后续扩展知识库等能力。

它适合先做：菜单和出门清单、邮件初稿、会议笔记整理、对公开资料的总结。它不适合替代医生、律师、投资顾问，也不该在第一天就装插件、开公网、导入证件、病历、客户资料、密钥或未脱敏日志。

**注意“本地”有边界**：模型可以在本机运行，但你接入外部 API、联网搜索、第三方插件、同步盘，或把 Open WebUI 暴露到局域网/公网后，数据路径都会改变。先把它当成一个小助手，不要当作绝对隐私保险箱。

### 1. 安装前准备：先过三道门

1. **电脑资源**：8GB 内存可以试小模型但可能较慢；16GB 内存通常更从容。显卡不是必需，但会影响速度。先从小模型开始，不要上来下载几十 GB。
2. **软件环境**：按本文主路线，你需要 Ollama 和 Docker Desktop；Windows 上 Docker Desktop 可能要求 WSL。Docker 没准备好时，先完成 Ollama 单独聊天也完全可以。
3. **测试资料**：第一次只用生活类或公开内容，不用真实敏感资料。

可从 Ollama Library 中按当前可用模型挑一个较小型号。本文用 `qwen3:4b` 举例；若你电脑资源紧张，也可在官方模型库中选择当日可用的更小模型。模型大小、显存/内存需求和表现会随版本不同而变化。

## 第二部分｜新手快速开始：先让本机模型开口，再打开网页界面

目标很简单：先完成一条可以验证的本地对话，再把它接进 Open WebUI。每走完一步都确认结果，别在问题还没定位时连着重装。

先选一条路线。Docker 还没有准备好，不是失败；你在终端完成第一条本地对话，就已经走完了今天最关键的半程。

**按你现在的状态选一条，别同时做三件事：**

1. **只想确认电脑能否跑本地模型**：今天只装 Ollama。`ollama run` 能完成一次低风险对话，就算过关。
2. **已经有 Docker Desktop，想用浏览器聊天**：继续装 Open WebUI。浏览器能在本机打开，并且能选到模型，就算过关。
3. **Docker 或 WSL 还没准备好**：先停在 Ollama。记录版本、模型名和终端结果，下次只处理 Docker，不用推倒重来。

### 1. 安装 Ollama，并确认本机模型能说话

到 Ollama 官方下载页选择系统安装包。Windows 用户如愿意执行官方联网安装脚本，可在 PowerShell 使用：

```powershell
irm https://ollama.com/install.ps1 | iex
```

不习惯运行联网脚本，就直接用官网安装包。安装完成后打开 PowerShell：

```powershell
ollama --version
ollama run qwen3:4b
```

第一次运行会下载模型。第一次慢一点很正常；先让它完成下载，再复制这段做第一次测试：

```text
请只根据下面的食材，给我两个 20 分钟内完成的早餐方案：
鸡蛋 4 个、青菜一把、挂面、牛奶、苹果。
每个方案要有步骤、用时和前一晚可准备的事项。
不要推荐我没有的食材；不确定的地方请标出来。
```

![终端中的三个确认位置：版本有输出、模型开始运行、能收到回答；为原创位置示意，非官方终端截图](assets/figures/14-Ollama + Open WebUI 新手教程：先把“本地 AI 助手”跑起来-正文插图02.png)

**先确认两个信号，再往下走：**终端能返回方案，且没有虚构你没提供的食材；`ollama --version` 有输出。若没做到，先检查模型名是否仍可在官方模型库找到、下载是否完成、电脑内存是否被其他程序占满。

想确认本地服务是否启动，可执行：

```powershell
Invoke-RestMethod http://localhost:11434/api/tags
```

能返回已安装模型列表，说明 Ollama 的本地 API 可访问。Docker 还没准备好时，停在这里并不算半成品：你已经能在自己的电脑上完成第一条本地对话。

### 2. 用 Docker 启动 Open WebUI

启动 Docker Desktop 后，在 PowerShell 运行官方 Quick Start 所示思路的 Docker 命令（不同平台与版本以官方页面为准）：

```powershell
docker run -d `
  -p 3000:8080 `
  --add-host=host.docker.internal:host-gateway `
  -v open-webui:/app/backend/data `
  --name open-webui `
  --restart always `
  ghcr.io/open-webui/open-webui:main
```

这几项新手只要理解三件事：

- `-p 3000:8080`：浏览器访问 `http://localhost:3000`；
- `-v open-webui:/app/backend/data`：保存聊天与配置，避免重建容器后直接丢失；
- `--add-host=host.docker.internal:host-gateway`：让容器可以找到本机的 Ollama 服务。

打开 `http://localhost:3000`，按界面创建本地账号，并在模型选择处寻找刚刚安装的模型。**看到界面但没有模型**，不代表失败：先回到终端执行 `ollama list`，再核对 Open WebUI 的 Ollama 连接地址是否指向本机服务。

![浏览器中需要确认的位置：本机地址、模型下拉和第一条测试任务；为原创操作位置示意，非官方界面截图](assets/figures/14-Ollama + Open WebUI 新手教程：先把“本地 AI 助手”跑起来-正文插图03.png)

**成功信号**：浏览器通过本机地址打开；模型下拉列表里能看到刚才下载的模型；把早餐任务发送后，回答来自同一个本地模型。
**失败时先看**：先执行 `docker ps`，再看端口是否被占用、Open WebUI 到 Ollama 的连接地址是否可达。一次只定位一层，不要同时重装 Docker、重新下载模型和改端口。

> `:main`、`:latest` 等镜像标签可能跟随项目更新，不等同于固定稳定版。家庭长期使用前，请回到 Open WebUI 当前官方文档确认推荐标签、升级方式与备份方案；不要把旧博客中的版本号当成永久答案。

### 3. 在网页里完成一件你今晚真会用的小事

进入 Open WebUI 后，先选中本地模型，再把刚才的早餐任务复制进去。接着追加一句：

```text
请把答案分成三块：确定来自我提供信息的内容、你的推断、需要我补充的信息。
```

这一步很关键。你不是在测试它会不会“说得漂亮”，而是在练习分辨：哪些是事实，哪些是它的建议。

再做一个工作生活里常见、风险较低的练习：

```text
请帮我把下面的话改成一封自然、礼貌、不卑微的请假邮件。
背景：孩子在 2026-08-14 上午需要复查，我想请半天假。
要求：不透露具体病情；说明我会提前交接待办；不要使用生硬套话。
原文：明天上午有点事，请假半天。
```

![把第一个生活问题拆成可执行任务卡：输入事实、限制、输出格式和验收方式](assets/figures/14-Ollama + Open WebUI 新手教程：先把“本地 AI 助手”跑起来-正文插图04.png)

**图 4｜问得更清楚，不是“会提示词”，而是把已有事实、限制和想要的交付说完整。**

**成功信号**：早餐回复不把不存在的食材写进去；请假邮件不暴露具体病情，并保留交接承诺。若它把推断写成事实，就把“事实 / 推断 / 待确认”这条要求保留在下一次提问里，并回到原始信息核对。

## 第三部分｜常见设置与高频卡点：用得稳，比装得快更重要

第一次跑通后，真正影响体验的往往不是“换哪个模型”，而是资源、连接、数据位置和提问边界。先按现象排查，再决定是否调整配置。

### 1. 常见卡点：按顺序排，不要盲目重装

**按下面顺序查，不要一报错就重装：**

1. **`localhost:3000` 打不开**：运行 `docker ps`，再运行 `docker logs open-webui`。先别删除数据卷重装。
2. **Open WebUI 看不到模型**：运行 `ollama list`，核对本机服务与连接地址。先别反复下载多个大模型。
3. **回答很慢**：换小模型、关闭占内存程序、缩短一次任务。慢不一定等于安装出错。
4. **回答像真的却不可靠**：要求它区分事实、推断、待确认项，再由你回到原始信息核对。不要把它当专业结论。
5. **想给家人或同事用**：先评估账号、聊天记录、端口和访问范围。不要直接暴露到公网。

如果端口 `3000` 被占用，可将 `-p 3000:8080` 改为另一个本机端口，例如 `-p 3001:8080`，再访问 `http://localhost:3001`。更改前确认该端口没有被你需要的服务占用。

### 2. 今天可以停在这里：保留你刚才的问题

做到下面四项，就可以先停：

- `ollama list` 能看到一个模型；
- 浏览器能打开 Open WebUI；
- 能在网页里选中本地模型并完成一次早餐/邮件任务；
- 你保留了一条“事实 / 推断 / 待确认”分开的回答。

下一次再考虑知识库、联网搜索或多人协作。今天到这里就好：把刚才那条早餐或邮件任务留住。下一次食材、时间或对象变了，只改那几行事实，不必从头再问。

### 3. 哪些情况先不要继续扩展

- 只需要偶尔问一个简单问题：先停在 Ollama 终端即可，没必要为了界面再花时间维护容器。
- 电脑持续卡顿、频繁内存不足：换更小模型或先释放资源，不要用下载更多大模型来“解决”速度问题。
- 打算把入口交给家人、同事或外网用户：先分别确认账号、聊天记录、端口、备份和访问范围；本地运行不等于默认适合共享。

把图 4 留在手边。每次提问只补齐“事实、限制、格式、验收”四项；你会发现，下一次同类问题不必从头描述，答案也更容易核对。
