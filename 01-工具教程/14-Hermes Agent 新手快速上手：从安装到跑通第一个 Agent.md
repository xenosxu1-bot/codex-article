> 一句话结论：第一次使用 Hermes Agent，只要跑通一条受控闭环：同一环境启动、模型完成真实回复、只读任务留下文件证据、会话能够续接。工具、Gateway、Skills 和自动化都放到下一轮。

新手最常见的失败并非安装命令本身，而是一次打开太多能力：模型、终端工具、消息 Gateway、Skills、MCP 同时配置。出现问题后，很难分清是环境、认证、模型、权限还是外部连接造成的。

更稳的做法是先完成一件可复核的小事，再逐层增加能力。本文按 Hermes Agent 当前官方快速入门整理出一条 30 分钟路径；具体安装命令、Provider、工具和平台支持会更新，执行前请回到 [Hermes Agent 官方快速入门](https://hermes-agent.nousresearch.com/docs/zh-Hans/getting-started/quickstart) 与 [安装说明](https://hermes-agent.nousresearch.com/docs/zh-Hans/getting-started/installation) 核对。

*图 1：Hermes Agent 官方简体中文快速入门页面。先跑通一条基础路径，再决定是否增加工具和自动化。*

## 一、先把能聊天与能交付分开

能回复一句话，只能证明模型、认证和终端之间有了连接。对一个 Agent 来说，更重要的是它能否在明确边界内读取信息、使用允许的工具，并留下可复核的结果。

第一次练习只看四个结果：

1. 在一套固定终端环境中启动，不在 PowerShell、Git Bash 与 WSL 之间来回切换。
2. 通过 hermes model 选定 Provider 与模型，并完成一次真实对话。
3. 对一个指定目录执行只读任务，每个结论都能指出对应文件。
4. 通过 hermes --continue 恢复会话后，仍能保留任务限制和已确认的事实。

四项都成立，才算完成首个 Agent 闭环。没完成前，不要急着把更多功能当成解决方案。

## 二、第一次运行前，先写下三条边界

提示词里的不要修改不能替代权限控制。第一次运行前，先把能力、数据和写入范围确定下来。

- **能力边界**：只启用本次任务必需的工具。练习目录阅读时，不需要消息平台、浏览器、定时任务或外部连接。
- **数据边界**：选择测试目录或非敏感项目。密钥、客户资料、生产配置和私人文件，不适合作为第一次练习材料。
- **写入边界**：默认只读。需要修改时，先要求说明计划和受影响文件，再查看 diff，最后由人决定是否执行。

![Agent 首次运行的三条边界](<../08-素材库/图片/正文插图/14-Hermes Agent 新手快速上手：从安装到跑通第一个 Agent-正文插图06-三条边界.png>)

*图 2：Hermes Agent 官方简体中文工具页面。工具越多，越要先收紧本次任务的能力范围。*

官方文档将 hermes tools 用于调整各平台启用的工具，并把 Gateway、Skills 等能力放在基础对话之后。第一次只要让最小任务可控，不必把所有入口都配齐。

## 三、安装与模型配置只走一套环境

Windows 用户应优先使用官方安装说明中的 Windows 路径；官方文档当前提供 PowerShell 安装方式，并说明原生 Windows 可运行 CLI、Gateway、TUI 和工具。执行任何远程安装脚本前，先确认域名、阅读页面的适用说明，并只从官方页面复制命令。

安装完成后，先在同一个终端里做两件事：

> 1. 运行 hermes doctor，查看基础环境与配置诊断。
> 2. 运行 hermes model，选择 Provider 和模型，然后完成一次真实回复。

如果回复为空、认证失败或模型表现异常，先不要继续接 Gateway。按官方快速入门的恢复顺序，依次检查 hermes doctor、hermes model 与 hermes setup；每改一项，就重新验证普通对话。把终端环境、Provider、模型和报错原文记下来，后续排查才不会变成猜测。

## 四、中间十分钟：只做一个可复核的只读任务

第一次任务最好选当前目录，但要把范围写得非常具体。下面这张任务卡可以直接复制给 Hermes：

> **第一次只读任务卡**
>
> 请只读当前目录，不要修改文件，也不要执行会改变环境的命令。
>
> 1. 判断这可能是什么项目。
> 2. 找出最可能的启动入口。
> 3. 找出测试、构建或检查命令。
> 4. 每个结论后标明依据文件；无法确认的内容明确写为推断。
> 5. 最后给出不超过 8 条的新手上手清单。

验收时不需要评价它聪不聪明，只检查三件事：它提到的文件是否存在；结论能否回到文件中核对；未知项有没有被如实标为推断。只有这三点都成立，才把任务结果当成下一步工作的输入。

## 五、最后十分钟：验证会话是否真的能续接

一轮任务完成，不代表上下文已经可靠保存。官方快速入门将 hermes sessions list 与 hermes --continue 作为会话恢复工具。先列出已有会话，再恢复刚才的会话，并补一个受限任务：

> 基于刚才读取的 README 和配置文件，整理一个 30 分钟上手计划。保留已确认的文件依据；没有证据的内容不要补写；不要修改任何文件。

![Agent 的可核查任务闭环](<../08-素材库/图片/正文插图/14-Hermes Agent 新手快速上手：从安装到跑通第一个 Agent-正文插图04.png>)

*图 3：Hermes Agent 官方简体中文快速入门页面中的首次对话与会话验证说明。*

合格标准不是计划写得漂亮，而是它仍保留只读限制、已确认文件和未确认项。限制条件或事实依据在续接后丢失时，先把会话恢复记为未验证，再回到普通对话和会话列表排查，而不是马上叠加配置。

## 六、把交接包写给下一次自己，也写给协作工具

从 Agent 得到的结果，如果只停在聊天记录里，下一次仍要重新探索。每次完成可复核任务后，整理一份简短交接包：

1. 当前目录或仓库是什么。
2. 已确认的关键文件和结论是什么。
3. 哪些范围允许修改，哪些范围禁止触碰。
4. 已经运行过哪些命令，结果如何。
5. 还有哪些未确认项，下一步用什么标准验收。

![Hermes Agent 快速参考](<../08-素材库/图片/正文插图/14-Hermes Agent 新手快速上手：从安装到跑通第一个 Agent-正文插图05-Codex对比.png>)

*图 4：Hermes Agent 官方简体中文快速参考页面。交接时优先留下命令、证据、限制与未确认项。*

这份交接包可以放在项目规则、任务卡或交接文档中。无论下一步继续使用 Hermes，还是切换到其他编程工作台，接手者都能从确定事实继续，而不是从一段长聊天记录里猜上下文。

## 七、按能力阶梯增加工具，而不是一次全开

基础闭环稳定后，再按照下面的顺序扩展：

1. L1，只读认识环境：读目录、找入口、解释配置。验收是文件证据可核对。
2. L2，受控修改：只改一个测试文件，先看计划与 diff，再运行单项验证。验收是改动与结果可复盘。
3. L3，项目协作：加入项目规则、任务模板和测试命令。验收是修改范围、验收标准和回退办法明确。
4. L4，外部连接与自动化：最后再配置 Gateway、Skills、MCP、定时任务和消息渠道。验收是权限、数据范围与失败处理已写清。

![Agent 能力升级阶梯](<../08-素材库/图片/正文插图/14-Hermes Agent 新手快速上手：从安装到跑通第一个 Agent-正文插图07-升级阶梯.png>)

*图 5：Hermes Agent 官方简体中文快速入门页面中的能力扩展提示。先验证上一层，再增加下一层。*

固定步骤、固定输入、固定输出的工作，先写成任务模板或 workflow 往往更稳。只有任务确实需要根据环境反馈选择工具和下一步时，再把动态决策交给 Agent。

## 八、今天只完成这五步

1. 在一套固定终端环境中安装并启动 Hermes。
2. 用 hermes doctor 与 hermes model 跑通一次普通对话。
3. 对非敏感目录执行一张只读任务卡。
4. 用 hermes sessions list 和 hermes --continue 验证会话恢复。
5. 写下交接包，再从一个很小的 L2 修改任务开始。

完成这五步后，你已经拥有一条可检查、可暂停、可继续的起点。Gateway、Skills、MCP 和自动化不是被放弃，而是等基础路径有证据后再逐项接入。
