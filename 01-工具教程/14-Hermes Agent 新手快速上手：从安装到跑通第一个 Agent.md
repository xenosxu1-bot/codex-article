> 一句话结论：第一天只验证 Hermes 能启动、模型能回复、只读任务有证据、会话能续接；工具、外部连接和自动化要等边界清楚后再增加。

第一次使用 Agent，最容易出的问题不是装不上，而是一次配置太多：模型、工具、Gateway、Skills、MCP 一起开，最后无法判断哪一项真正有效，也不知道哪一项带来了风险。

新手第一天的目标不是造出全能助手，而是跑通一条能解释、能复核、能继续的最小工作路径。

*图 1：Hermes Agent 官方简体中文 Quickstart 截图，重点看“最快路径”：先跑通最小闭环，再增加工具和自动化。*

## 一、Agent 是什么：先把能聊天和能交付分开

聊天工具主要给出回答；Agent 会在运行环境中读取上下文、调用工具、接收反馈，并决定下一步是继续、等待确认还是停止。它通常包含四个部分：模型、工具、状态和权限。

- 模型： 理解目标，提出计划，解释结果。
- 工具： 读取文件、运行命令、搜索资料或连接外部服务。
- 状态： 保留当前会话、已读文件和未完成事项。
- 权限： 限定它能查看什么、能修改什么、什么时候必须等人确认。

因此，判断 Agent 是否有用，不看它回答得多像人，而看它能否在清楚边界内留下可核对的交付。

## 二、今天是否成功，只看四个验证点

第一天只验收下面四件事：

1. **环境稳定：** 能在同一终端环境中启动，不需要反复切换 PowerShell、Git Bash 或 WSL。
2. **模型可用：** `hermes model` 能完成一次明确回复。
3. **结果可核对：** 它能只读一个目录，并把每条结论对应到具体文件。
4. **会话可续接：** `hermes --continue` 后仍能保留前一次任务的限制和文件证据。

四项都成立，才算完成第一天。Gateway、Skills、MCP 不是少学了，而是放到有依据的第二轮。

## 三、第一次运行前，先画出三条边界

提示词里的不要修改不能替代实际权限。第一次运行前，先把能力、数据和写入范围写清楚。

- 能力边界： 只开完成本次任务所需的工具。第一次只做目录阅读，不需要浏览器、外部连接或定时任务。
- 数据边界： 选测试目录或非敏感项目。密钥、客户资料、生产配置和私人文档不应成为首次练习素材。
- 写入边界： 默认只读。需要改文件时，先让它说明计划、展示 `diff`，再由你决定是否执行。

![Agent 首次运行的三条边界](<../08-素材库/图片/正文插图/14-Hermes Agent 新手快速上手：从安装到跑通第一个 Agent-正文插图06-三条边界.png>)

*图 2：Hermes Agent 官方简体中文“工具与工具集”截图，首次运行前先看清工具面，再收紧能力、数据和写入范围。*

Hermes 的工具体系可以覆盖终端、文件、浏览器、搜索、记忆、委派、定时任务和 MCP 等不同能力。功能越多，越需要先把本次任务的工具面收窄，而不是只靠一句提示词约束它。[工具说明](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/tools.md) 可以作为后续扩展时的核对入口。

## 四、前十分钟：只把环境与模型跑通

先按 [Hermes Agent Quickstart](https://hermes-agent.nousresearch.com/docs/getting-started/quickstart) 和 [Installation](https://hermes-agent.nousresearch.com/docs/getting-started/installation) 选择安装方式。第一次安装、配置和运行尽量都放在同一套终端环境里，避免把不同环境的配置混在一起。

安装后只做两件事：

1. 运行 `hermes doctor`，确认基础环境和诊断结果。
2. 运行 `hermes model`，确认当前模型能完成一次回复。

如果这里不稳定，按 `hermes doctor` → `hermes model` → `hermes setup` 的顺序逐项排查。每做完一步都重新启动一次，不要同时改模型、终端和外部连接。

## 五、中间十分钟：只做一个可复核的只读任务

第一次任务最适合选当前目录，但范围要明确为读取和说明。下面这张任务卡可以直接使用：

> **第一次任务卡**
>
> 请先只读当前目录，不要修改任何文件，也不要执行会改变环境的命令。
>
> 1. 判断这可能是什么项目。
> 2. 找出最可能的启动入口。
> 3. 找出测试、构建或检查命令。
> 4. 每个结论后标明它来自哪个文件；无法确认的内容明确写为推断。
> 5. 最后给我一份不超过 8 条的新手上手清单。

验收时不需要相信它看起来很聪明。只检查三件事：它提到的文件是否存在，结论能否回到文件中核对，未知部分有没有明确标为推断。

这一步也给后面的 Codex 交接留下基础材料：你已经知道项目从哪里启动，哪些文件是证据，哪些问题还不能确定。

## 六、最后十分钟：验证会话和交接能不能接上

一次任务做完，不等于它能持续工作。把刚才的任务留在同一会话中，再验证一次续接：

> - 续接会话：`hermes --continue`
> - 列出会话：`hermes sessions list`

续接后给出这句要求：

> 基于刚才找到的 README 和配置文件，把上手清单改成一个 30 分钟执行计划。保留文件证据，不确定的地方不要补写。

![Agent 的可核查任务闭环](<../08-素材库/图片/正文插图/14-Hermes Agent 新手快速上手：从安装到跑通第一个 Agent-正文插图04.png>)

*图 3：Hermes Agent 官方简体中文“运行第一次对话 / 验证会话功能”截图，一次任务应形成读取、检查和结果回传的闭环。*

合格标准不是计划写得漂亮，而是它仍引用刚才读过的文件，并保留只读、不确定不补写等限制。限制条件丢失时，先记为会话或上下文续接未确认，不要用增加配置来掩盖问题。

## 七、Hermes 和 Codex：按工作台分工，再用交接包连接

Hermes 与 Codex 不必先争谁更强。更实用的判断是：当前任务需要哪一种工作台，以及下一位执行者需要拿到哪些事实。

| 当前任务 | 更适合先做什么 | 交接时留下什么 |
| --- | --- | --- |
| 理解本地目录、会话与运行环境 | 用 Hermes 做只读探索和上下文续接 | 已读文件、结论、未确认项 |
| 推进仓库改动、检查 `diff`、运行验证 | 按现有 Codex 工作流实施与复核 | 修改范围、验证命令、验收标准 |
| 两个工具连续协作 | 先做探索，再做实现 | 一份明确的交接包 |

交接包至少写清五项：当前目录或仓库、已确认的关键文件、允许和禁止的修改范围、已经运行或仍需运行的验证命令、未确认项和验收标准。

[OpenAI Codex 官方仓库](https://github.com/openai/codex) 提供的是 Codex 的当前产品与使用入口；这里的分工是本文的工作建议，不是能力排名。把交接信息写进项目规则、任务卡或仓库文档，比复制一长段聊天记录更可靠。

![Hermes 与 Codex 的工作台差异示意图](<../08-素材库/图片/正文插图/14-Hermes Agent 新手快速上手：从安装到跑通第一个 Agent-正文插图05-Codex对比.png>)

*图 4：Hermes Agent 官方简体中文“快速参考”截图。交接给 Codex 或其他工作台前，先把命令、证据和未确认项整理成可复核清单。*

## 八、从只读到自动化：按四级阶梯增加能力

不要把 Gateway、Skills、MCP 当成同一天必须完成的清单。它们应该出现在下面的阶梯中：

1. L1，只读认识环境： 读目录、找入口、解释配置。合格标准是文件证据可核对。
2. L2，受控修改： 修改一个测试文件，先看计划和 `diff`，再运行单项验证。合格标准是改动与结果都能复盘。
3. L3，项目协作： 使用项目规则、任务模板和测试命令。合格标准是修改范围、验收标准和回退办法明确。
4. L4，外部连接与自动化： 再考虑 Gateway、MCP、定时任务和消息渠道。合格标准是权限、数据范围和失败处理已写清。

![Agent 能力升级阶梯](<../08-素材库/图片/正文插图/14-Hermes Agent 新手快速上手：从安装到跑通第一个 Agent-正文插图07-升级阶梯.png>)

*图 5：Hermes Agent 官方简体中文“添加下一层功能”截图。能力升级前，先确认上一层的证据、边界和回退路径。*

固定步骤、固定输入、固定输出的工作，先做成任务模板或 workflow 往往更稳；只有当任务需要根据环境反馈选择下一步工具时，再让 Agent 承担动态决策。这样能避免把每件小事都过度 Agent 化。

## 九、今天可以带走的最小行动清单

今天只完成五步：在固定终端启动 Hermes，用 `hermes model` 跑通一次模型回复，用只读任务卡检查一个目录，用 `hermes --continue` 验证续接，把结论整理成可交接的五项信息。

完成后，选择一个最小的 L2 任务，而不是立刻打开所有扩展能力。等你能解释每一步工具为什么存在、会接触什么数据、失败后怎样停下，Agent 才真正开始成为工作台的一部分。
