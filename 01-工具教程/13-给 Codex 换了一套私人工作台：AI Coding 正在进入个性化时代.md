> 一句话结论：私人工作台不是把 Codex 变得更花哨，而是让项目、输入、任务状态和恢复入口都更容易找到；皮肤只应服务这件事。

每天反复打开 Codex 后，侧栏、任务页和输入框会慢慢变成工作节奏的一部分。真正拖慢人的，往往不是少一个功能，而是找不到刚才的项目、看不清当前状态，或者担心一次主题更新会打断手上的任务。

这也是 AI 工具需要私人空间的原因。它不只是你的视觉偏好，还应该帮你保留注意力、减少切换，并在异常时回到可靠状态。

## 一、故事开场：AI 工具为什么需要私人空间

同一个 Codex 界面，有人打开后马上能继续昨天的任务，有人却要先找项目、找输入框、找上下文。差别不在于谁的背景图更漂亮，而在于工作台有没有把高频动作放在清楚、稳定的位置。

私人空间的价值可以落在四件小事上：

1. 一眼定位： 当前项目、任务状态、输入区域和发送入口不需要反复寻找。
2. 减少干扰： 背景、颜色和动画不抢正文与操作区的注意力。
3. 保留上下文： 常用项目、任务模板和规则入口有固定位置。
4. 随时恢复： 主题异常或客户端升级后，能先回到原始界面，再继续排查。

如果一套皮肤不能让这四件事更轻松，它再适合截图，也未必适合日常使用。

## 二、一个趋势：AI Coding 进入个性化时代

AI Coding 的个性化，不该只理解成颜色、壁纸和字体。真正值得投入的是把工作环境调成适合自己推进任务的样子：人能快速看清任务，Agent 能找到项目规则，出现问题时双方都有明确的停止和恢复路径。

对个人来说，这是一套更顺手的桌面；对长期使用 Agent 的人来说，它还是一套可发现的工作上下文。项目入口、任务模板、`AGENTS.md`、验证命令和重要资料如果分散在各处，界面再好看也不能减少真正的协作成本。

所以，皮肤是入口，工作流才是长期收益。下一篇 [《Hermes Agent 新手快速上手：从安装到跑通第一个 Agent》](<14-Hermes Agent 新手快速上手：从安装到跑通第一个 Agent.md>) 讲的正是工作台另一面：怎样让 Agent 在明确边界内读取、验证和交接工作。

## 三、Dream Skin 是什么

Dream Skin 是 Codex 的第三方主题项目，不是官方功能。它提供主题、背景和更个人化的视觉层，但不会替你完成模型选择、权限确认、任务拆分或结果验收。

把它放在外观层最合适：它应该帮助阅读、定位和输入，而不是覆盖原有的信息层级。项目当前 README 说明，普通用户优先使用 [Release 页面](https://github.com/Fei-Away/Codex-Dream-Skin/releases) 提供的图形安装包；准备参与开发时，才需要进入源码、依赖和构建流程。

这也是为什么安装前先分清两类需求：

- 日常使用： 只安装发布包、选主题、在空白任务中验证。
- 参与开发： 才关心仓库、依赖、构建和调试。

不要为了换一套主题，把自己带进并不需要的开发环境。

## 四、我的实际体验：用任务页而不是截图判断

判断主题是否值得保留，我不看宣传图，直接打开一个空白任务页，做下面三项检查：

1. 导航是否清楚： 左侧项目、任务列表和当前选中状态能否一眼分辨。
2. 输入是否顺手： 输入框、发送入口和回显区域是否始终可见，文字对比是否足够。
3. 长内容是否稳定： 打开任务卡、滚动较长内容、回到输入区时，布局是否仍然清楚。

## 五、为什么不是简单换背景

背景只是视觉的一部分。真正的个人工作台至少有五层：外观、导航、任务、知识和恢复。外观帮你减少视觉噪声；导航帮你回到项目；任务让当前工作可见；知识为人和 Agent 提供规则；恢复确保出问题时不会把重要工作一起带走。

## 六、安装教程：用十分钟跑通最小验证

第 1 步：先退出 Codex 或 ChatGPT 桌面端，保存尚未发送的内容。不要在正在推进的重要任务旁边试主题。

第 2 步：进入 [Dream Skin Release 页面](https://github.com/Fei-Away/Codex-Dream-Skin/releases)，下载与当前系统匹配的发布安装程序。普通用户按当前 README 所示运行 `CodexDreamSkin-Setup-v*.exe`，无需为了安装主题额外 clone 仓库、安装 Node.js 或手动执行源码脚本。

第 3 步：重新启动应用，先新建一条空白任务。依次完成输入一段文字、切换项目、打开任务卡、滚动长内容、回到输入区域这五步。

第 4 步：最后再导入自己的背景。只使用你拥有或已获授权的 PNG、JPEG 或 WebP；先用低干扰图片确认布局，再决定是否保留更强的视觉效果。

这套顺序很短，但它把安装、日常使用和素材导入拆开了。出问题时，你能知道问题出在发布包、主题、背景，还是客户端本身。

## 七、安全注意事项：异常时先停止，再还原

Dream Skin 是第三方项目。它的 README 提供了主题包校验、安全 CSS 范围和恢复思路，但这些措施不是对所有风险的绝对保证。来源不明的主题包、脚本和图片，仍然不应该直接导入工作环境。

出现遮挡、错位、卡顿或启动异常时，按这个顺序处理：

1. 停止继续覆盖安装或追加设置。
2. 使用当前版本提供的还原入口恢复默认外观。
3. 重启应用，并在空白任务页验证基础界面。
4. 记录客户端版本、主题版本、问题页面和还原结果。

不要凭感觉修改系统目录，也不要让 Agent 直接执行未知的修复命令。若需要排查，先给它只读范围：读取主题目录和日志，列出疑点与建议，不修改文件、不运行安装脚本。

## 八、适合哪些人

适合尝试的人，通常已经高频使用 Codex，知道自己最常看的区域，并愿意留出十分钟做空白任务验证。

如果你正在赶交付、基础界面问题还没定位、没有恢复路径，或主题来源不清楚，先不要折腾。此时最有价值的优化不是视觉升级，而是把项目入口、当前任务和重要资料整理到容易找到的位置。

## 九、未来：每个人都会拥有自己的 AI 工作台

未来的个人工作台不会只区分代码编辑器、聊天窗口和资料库。它会把常用项目、任务边界、验证方式和个人偏好组织在同一条工作路径上。

其中一部分属于界面：让人看得清楚、用得顺手；另一部分属于规则：让 Agent 知道该读什么、能改什么、交付后怎样验证。两者缺一个，所谓个性化都容易退回成短暂的新鲜感。

## 十、总结：今天先做一次工作台体检

今天不必追求一整套复杂主题。只做四件事：确认主题来自哪里，完成一次空白任务验证，记下恢复入口，把常用项目和规则放到固定位置。

完成后，再决定这套皮肤是否值得留下。真正好的私人工作台，不会让你多花时间照顾它，而会让你更快回到正在做的事。
