17. DeepSeek Harness 新手教程：别急着让 AI 改代码，先把第一个 Agent 任务跑起来

第一次打开 DeepSeek Harness，最容易犯的错误，不是不会配置，而是把真实项目直接交出去，然后对 AI 说：“帮我把这个需求做完。”

那一刻你可能既期待又有点紧张：它如果真的能读懂项目，效率会很高；可如果它跑错目录、改错文件，甚至顺手执行了你没想到的命令，后悔往往比等待更快到来。

所以第一次接触 Agent，不要先追求“让它写出多少代码”。先确认三件事：它正在看哪个目录、准备做什么、哪一步会停下来等你确认。今天我们只完成一个安全的第一次体验：启动工作台、让模型回复一句话、读取练习目录，再批准一次“只创建一个小文件”的动作。

![DeepSeek Harness 官方中文文档操作路径图（编辑重绘）](<assets/figures/17-DeepSeek Harness 新手教程：别急着让 AI 改代码，先把第一个 Agent 任务跑起来-官方中文指南操作路径图.png>)

把这张图当成第一次上手的路线卡：先启动，再设置模型；模型能回复后，选择工作区；最后才发送任务并处理审批。页面入口可能随开发者预览版本变化，但这个顺序值得保留。


这次跑通后，你应该能拿到三个看得见的结果：模型能正常回复、Agent 只读了你指定的练习目录、获得批准后只新增一个可删除的小文件。只要这三项没有同时出现，就还不算“会用了”。

第一次先别做三件事：不要把真实仓库当沙盒，不要一开始同时打开写入、删除和联网权限，也不要把 Key 贴进对话或提交到项目里。先把风险关在一个能随时删掉的目录里，学习成本会低很多。

## 先把它看成一个“有手脚的协作者”

DeepSeek Harness 是 DeepSeek 开源的开发者预览项目。它不是新的大模型，也不是一句话就能替你改完整个项目的魔法按钮。更准确地说，它把模型、工作区和可执行动作放到同一张桌面上，同时给你留下查看计划、限制范围和审批动作的机会。

对新手来说，先理解三件事就够了：

- **模型设置**：决定工作台使用哪个模型、服务商和凭据；
- **工作区**：决定 Agent 能查看和操作哪一个目录；
- **计划与审批**：在读取、写入或运行命令前，给你一次判断影响范围的机会。

它适合先做读目录、解释文件、列计划，或者在练习目录里创建一个可删除的小文件。暂时不要拿它直接处理客户资料、批量替换、安装未知依赖、删除文件、读取密钥或碰线上环境。

## 第一次别碰真实仓库，给它一个可以犯错的房间

先打开 **PowerShell**，确认 Node.js 和 npm 可用：

```powershell
node -v
npm -v
```

两行都能返回版本号后，创建一个只属于这次练习的目录。下面使用用户目录变量，不绑定某台电脑的盘符：

```powershell
$playground = Join-Path $HOME 'dsh-playground'
New-Item -ItemType Directory -Force -Path $playground, (Join-Path $playground 'docs'), (Join-Path $playground 'notes')
Set-Location $playground
Set-Content -LiteralPath .\README.md -Encoding utf8 -Value '# DeepSeek Harness 练习项目', '', '目标：只在这个目录练习 Agent 的读取、计划与最小写入。'
Set-Content -LiteralPath .\docs\todo.md -Encoding utf8 -Value '待办：整理 README，先不要修改任何文件。'
Get-ChildItem -Recurse -File
```

你应该能看到 `README.md`、`docs/todo.md` 和空的 `notes` 文件夹。看不到时先执行 `Get-Location`，确认当前路径仍然是刚才的练习目录，不要急着重复创建。

接着仍在这个 PowerShell 窗口启动 Web UI：

```powershell
npx @deepseek-ai/dsh web
```

首次运行可能会下载并初始化。保持终端打开，在浏览器访问：

```text
http://127.0.0.1:3080
```

进入 **设置 → 模型**，按当前页面填写提供商或接口类型、模型名称和 API Key，并确认保存成功。字段名称可能变化，但有一条原则不会变：Key 只留在本机设置里，不要发进会话，不要写进 Markdown，也不要提交 Git。

![DeepSeek Harness 第一次使用的四步安全闭环（原创信息图）](<assets/figures/17-DeepSeek Harness 新手教程：别急着让 AI 改代码，先把第一个 Agent 任务跑起来-正文插图01.png>)

现在先别给它真正的开发任务。发送一句最简单的话：

```text
请只回复：模型连接正常。
```

能得到明确回复，第一关就过了。没有回复时，回设置页检查模型名、服务商、兼容端点和 Key，不要把 Key 粘到聊天窗口里“测试”。

## 先让 Agent 只读，再允许它留下一个小脚印

模型能回复后，先把刚才的练习目录添加为工作区，然后发送一条只读任务：

```text
只在当前工作区执行。
请读取 README.md、docs/todo.md 和 notes 目录，告诉我：
1. 当前有哪些文件；
2. README.md 与 docs/todo.md 分别写了什么；
3. 下一步可以做什么，但不要实际执行。
限制：不要创建、修改、删除文件；不要联网、安装依赖或执行其他命令。
```

这一步不要只看回答像不像。你要看的是：它有没有只谈当前工作区，能不能分清“文件里已有的内容”和“下一步建议”，有没有偷偷申请写入、下载或修改。只读任务一旦越界，就拒绝这次动作，把任务改得更小。

只读任务通过后，再允许它做一件可回退的事：

```text
只在当前工作区执行。
请先展示准备创建的相对路径、文件中的三条要点，以及不会执行的其他动作。
等待我确认后，只创建 notes/first-task.md。
文件写入：本次练习目标、刚才完成的只读检查、我如何验证结果。
禁止修改其他文件；禁止删除、联网、安装依赖和执行批量命令。
```

![Agent 审批前的四个检查问题（原创信息图）](<assets/figures/17-DeepSeek Harness 新手教程：别急着让 AI 改代码，先把第一个 Agent 任务跑起来-正文插图02.png>)

出现计划或审批卡片时，先别被一长串“看起来很完整”的动作说服。只核对四件事：路径是不是 `notes/first-task.md`，动作是不是只有创建这一个文件，没有下载、安装、删除或联网，写错后能不能只删掉这一个练习文件。

四项都符合，再允许继续。完成后回到 PowerShell 亲手验收：

```powershell
Get-ChildItem -Recurse -File
Get-Content -LiteralPath .\notes\first-task.md
```

新增的应该只有 `notes/first-task.md`，原来的两个测试文件仍然在，内容也能对应任务要求。你看到的不是“AI 很聪明”，而是一次可观察、可回退的协作。第一次体验真正有价值的地方，恰恰是你知道自己允许了什么。

## 从练习目录走向真实项目，慢一点反而更快

准备进入真实仓库前，先看一眼现状：

```powershell
git status --short
git branch --show-current
```

第一次给真实项目的任务，仍然可以只是：“说明目录结构、找出入口文件、列出可能相关的三个文件，但不要修改。”等你确认它读对了目录、理解了目标，再给一个范围很小、可以回滚的修改。

日常最容易卡住的地方，也可以按这个顺序判断：

- **页面打不开**：回启动终端看第一条报错，确认地址是否仍是 `127.0.0.1:3080`；
- **模型没有回复**：回设置页检查 Key、模型名、服务商或兼容端点；
- **输入区不可用**：确认已经添加并选中了练习目录；
- **计划超出预期**：拒绝动作，让 Agent 缩小范围并重新展示计划。

当你把这套节奏带进真实仓库，Agent 才会从“让人兴奋的演示”变成“可以合作的工具”：先读，再说；先计划，再动手；先小范围验证，再逐步扩大权限。

## 你学会的不是让 AI 更快，而是让协作更稳

第一次上手 DeepSeek Harness，不需要一次学完所有设置，也不需要立刻证明它能替你写完整个项目。你只要完成这条闭环：模型能回复，工作区选对了，任务边界写清楚，审批前看过计划，写入后亲手验收。

等哪天你把它接进真实项目，仍然记得今天那个练习目录。真正成熟的使用方式，不是把所有决定交给 Agent，而是始终知道：它在哪儿、要做什么、你允许到哪一步，以及出了问题怎样退回来。
