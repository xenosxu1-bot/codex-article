17. DeepSeek Harness 新手教程：别急着让 AI 改代码，先把第一个 Agent 任务跑起来

第一次打开 DeepSeek Harness，最容易犯的错误，不是不会配置，而是直接把真实项目交出去，然后对 AI 说：“帮我把这个需求做完。”

你当然会期待：如果它真的能读懂项目，写代码、跑命令、整理文件的速度都可能变快。但紧张也很正常——它到底看的是哪个目录？准备执行哪些动作？如果改错了，能不能只退回这一小步？

所以第一次接触 Agent，不要先追求“让它写出多少代码”。先完成一个更重要的结果：**你能看见它在哪里工作、准备做什么，并且在动作发生前做决定。**

本文带你在一个随时可以删除的练习目录里完成一条最小闭环：启动 Web UI、配置模型、选择工作区、让 Agent 只读一次，再批准它只创建一个小文件。跑通后，你会知道 Agent 和普通聊天机器人到底差在哪里，也知道什么时候可以把它带进真实项目。

![DeepSeek Harness 官方中文文档操作路径图（编辑重绘）](assets/figures/17-DeepSeek Harness 新手教程：别急着让 AI 改代码，先把第一个 Agent 任务跑起来-官方中文指南操作路径图.png)

这次练习的验收标准只有三个：模型能正常回复；Agent 只读取你指定的目录；获得批准后只新增一个可删除的小文件。三项没有同时出现，就还不算真正会用。

## 一、它和普通聊天工具有什么不同？

DeepSeek Harness（命令行入口是 `dsh`）是 DeepSeek AI 开源的 Agent Harness，目前仍处于开发者预览阶段。你可以把它理解成一张“模型、项目文件和可执行动作”放在一起的工作台。

普通聊天工具主要负责回答问题；Harness 还会围绕一个工作区进行读取、规划和动作执行。对新手来说，最关键的不是记住“Agent”这个词，而是理解下面三层关系：

- **模型**：负责理解你的任务并生成计划或回答；
- **工作区**：决定它可以看到哪一个项目目录；
- **计划与审批**：在读取、写入或运行命令前，让你有机会查看影响范围。

它适合做项目结构说明、文件摘要、任务拆解和小范围修改。不适合一上来就处理客户资料、线上环境、密钥文件、批量删除或未知依赖安装。

## 二、先准备一个可以犯错的房间

开始前只需要确认：电脑已经安装 Node.js，并且 PowerShell 能识别 `node` 和 `npm`。先运行：

```powershell
node -v
npm -v
```

两行都能返回版本号后，创建本次专用的练习目录。下面的写法使用当前用户目录，不依赖作者电脑的盘符：

```powershell
$playground = Join-Path $HOME 'dsh-playground'
New-Item -ItemType Directory -Force -Path $playground, (Join-Path $playground 'docs'), (Join-Path $playground 'notes')
Set-Location $playground
Set-Content -LiteralPath .\README.md -Encoding utf8 -Value '# DeepSeek Harness 练习项目', '', '目标：只在这个目录练习 Agent 的读取、计划与最小写入。'
Set-Content -LiteralPath .\docs	odo.md -Encoding utf8 -Value '待办：整理 README，先不要修改任何文件。'
Get-ChildItem -Recurse -File
```

你应该能看到 `README.md`、`docs/todo.md`，以及一个空的 `notes` 文件夹。看不到时，先执行 `Get-Location` 确认当前路径；不要在不确定目录的情况下重复创建或启动。

## 三、十分钟跑通第一次使用

### 1. 启动 Web UI

仍然在刚才的 PowerShell 窗口运行：

```powershell
npx @deepseek-ai/dsh web
```

首次运行可能下载并初始化依赖。保持终端窗口打开，访问终端打印出的地址；默认通常是：

```text
http://127.0.0.1:3080
```

启动时所在的目录会作为默认文件系统位置。全新的 Web UI 通常不会自动选中工作区，这正是接下来要手动确认的地方。

### 2. 配置模型，但不要把 Key 发到聊天里

打开 **设置 → 模型**，按照当前页面填写模型提供商、模型名称和 API Key，然后保存。不同提供商和兼容端点的字段可能不同，优先以当前官方 Providers 指南和页面提示为准。

Key 只放在本机设置中，不要粘贴到聊天窗口、练习文件、截图或 Git 提交里。模型调用可能产生费用，按你的服务商账号规则为准。

先发送一句最简单的话：

```text
请只回复：模型连接正常。
```

能得到明确回复，说明模型链路至少已经打通。没有回复时，先检查提供商、模型名、兼容端点和 Key，不要为了“测试 Key”把它复制到对话中。

![DeepSeek Harness 第一次使用的四步安全闭环（原创信息图）](assets/figures/17-DeepSeek Harness 新手教程：别急着让 AI 改代码，先把第一个 Agent 任务跑起来-正文插图01.png)

### 3. 添加并选中工作区

点击 **选择工作区**，添加刚才创建的 `dsh-playground`，再明确选中它。官方指南指出，未选中工作区前，输入区可能不可用；这不是故障，而是工具在提醒你先给 Agent 一个明确边界。

## 四、先做只读任务，再给它一个小权限

模型能回复、工作区也选中后，先发送只读任务：

```text
只在当前工作区执行。
请读取 README.md、docs/todo.md 和 notes 目录，告诉我：
1. 当前有哪些文件；
2. README.md 与 docs/todo.md 分别写了什么；
3. 下一步可以做什么，但不要实际执行。
限制：不要创建、修改、删除文件；不要联网、安装依赖或执行其他命令。
```

这一步不要只看回答顺不顺。你要核对三件事：它是否只谈当前工作区；能否分清“文件中已有的内容”和“下一步建议”；有没有申请写入、下载或修改。

只读任务通过后，再给一个单一、可回退的写入任务：

```text
只在当前工作区执行。
请先展示准备创建的相对路径、文件中的三条要点，以及不会执行的其他动作。
等待我确认后，只创建 notes/first-task.md。
文件写入：本次练习目标、刚才完成的只读检查、我如何验证结果。
禁止修改其他文件；禁止删除、联网、安装依赖和执行批量命令。
```

![Agent 审批前的四个检查问题（原创信息图）](assets/figures/17-DeepSeek Harness 新手教程：别急着让 AI 改代码，先把第一个 Agent 任务跑起来-正文插图02.png)

出现计划或审批卡片时，不要被一长串“看起来很完整”的动作说服。只核对四件事：

- 路径是不是 `notes/first-task.md`；
- 动作是不是只有创建这一个文件；
- 有没有下载、安装、删除、联网或批量命令；
- 写错后能不能只删掉这一个练习文件。

任何一项不符合，都可以拒绝这次动作，让 Agent 缩小范围后重新展示计划。拒绝不是“不会用”，而是你正在使用它最重要的能力：先看清楚，再决定是否执行。

批准后回到 PowerShell，亲手检查结果：

```powershell
Get-ChildItem -Recurse -File
Get-Content -LiteralPath .
otesirst-task.md
```

新增的应该只有 `notes/first-task.md`，原来的两个测试文件仍然存在，文件内容也能对应任务要求。到这里，你得到的不是一次“AI 很聪明”的演示，而是一条可观察、可回退、可复用的协作路径。

## 五、把第一次成功迁移到真实项目

进入真实仓库前，先让 Agent 做一个只读任务，例如：

```text
只读取当前工作区。
请说明项目目录结构，找出入口文件，并列出与“登录页面”最相关的三个文件。
不要修改文件、运行命令、安装依赖或联网。
```

确认它读对目录、理解了目标后，再给一个范围很小、可以回滚的修改。每次只改变一个变量：一个文件、一个功能、一个验收方式。完成后由你亲手查看差异、运行测试或打开页面，不要把“Agent 说完成了”当成验收结果。

它真正适合帮助你的地方，通常是：

- 第一次接手陌生项目时，快速建立目录地图；
- 把模糊需求拆成可执行任务；
- 在明确范围内生成或修改少量代码；
- 根据测试结果继续修正，而不是一次性猜完整个项目。

## 六、常见卡点与高频设置

- **页面打不开**：先看启动终端打印的地址；如果默认端口被占用，以终端实际输出为准。
- **`node` 或 `npm` 不识别**：确认 Node.js 安装完成后重新打开 PowerShell，再运行版本检查。
- **模型没有回复**：回到“设置 → 模型”检查提供商、模型名、兼容端点和 Key。
- **输入区不可用**：确认已经添加并选中了工作区。
- **计划超出预期**：拒绝动作，让 Agent 把范围缩小到一个文件或一个命令。
- **想直接扩大权限**：先问自己是否能解释每个动作的影响，以及有没有可恢复的备份或版本记录。

不要把开发者预览版当成稳定生产系统。它可能出现界面变化、命令变化和破坏兼容性的更新；真实项目中还要考虑权限、密钥、代码备份、依赖安装和命令副作用。

最后把这张任务卡留给自己：

```text
目标：我希望 Agent 帮我完成什么？
范围：它只能读取或修改哪些文件？
禁止：哪些动作绝对不能做？
审批：执行前我需要看到什么计划？
验收：我会用什么命令、差异或页面确认结果？
回退：做错后如何恢复？
```

你学会的不是让 AI 更快，而是让协作更稳。等你把 Agent 接进真实项目，仍然记得今天这个练习目录：先读，再说；先计划，再动手；先小范围验证，再逐步扩大权限。
