第一次打开 DeepSeek Harness，别急着把真实项目拖进去，更不要上来就说“帮我把这个需求做完”。

你现在只需要完成一件小事：**用一个空白练习目录，跑通“启动页面 → 配置模型 → 让 Agent 读文件 → 只创建一个练习文件”这条链路。**全程不碰真实代码、不贴真实 Key、不做不可逆操作。

照着本文操作，完成后你应该能看到 4 个结果：

- 本机浏览器能打开 DeepSeek Harness；
- 模型能正常回答一句不涉及工具的话；
- Agent 能说明 `D:\dsh-playground` 里有什么；
- 你能在审批后得到一个 `notes\first-task.md`，并亲手验证它没有改到别处。

![DeepSeek Harness 第一次使用的四步安全闭环（原创信息图）](assets/figures/17-DeepSeek Harness 新手教程：别急着让 AI 改代码，先把第一个 Agent 任务跑起来-正文插图01.png)

> **练习规则：**下面所有操作都在 `D:\dsh-playground` 完成。不要把桌面、下载目录、真实仓库、客户资料或含密钥的文件夹设为第一次工作区。

## STEP 01｜先准备命令行和练习目录（2 分钟）

打开 **PowerShell**，依次复制执行：

```powershell
node -v
npm -v
```

两行都能返回版本号，说明 Node.js 和 npm 可以使用。接着创建练习目录，并放入两个供 Agent 阅读的文件：

```powershell
mkdir D:\dsh-playground -Force
Set-Location D:\dsh-playground
New-Item -ItemType Directory -Force -Path .\docs, .\notes
Set-Content -LiteralPath .\README.md -Encoding utf8 -Value '# DeepSeek Harness 练习项目', '', '目标：只在这个目录练习 Agent 的读取、计划与最小写入。'
Set-Content -LiteralPath .\docs\todo.md -Encoding utf8 -Value '待办：整理 README，先不要修改任何文件。'
Get-ChildItem -Recurse -File
```

**你应当看到：**`README.md`、`docs\todo.md`，以及空的 `notes` 文件夹。看不到也没关系，先检查自己是否仍在 `D:\dsh-playground`：

```powershell
Get-Location
```

## STEP 02｜启动 Web 工作台（1 分钟）

仍在同一个 PowerShell 窗口中执行：

```powershell
npx @deepseek-ai/dsh web
```

保持这个终端窗口不要关闭。首次运行可能需要下载和初始化；当终端显示服务已启动后，在浏览器打开：

```text
http://127.0.0.1:3080
```

**本步完成标准：**浏览器能打开本地工作台，且启动命令仍在终端持续运行。页面暂时打不开时，不要连续执行多次启动命令；先回到终端看第一条报错，再排查端口、网络或依赖下载问题。

## STEP 03｜在页面里配置模型，并只验证“能回答”（3 分钟）

在 Web UI 中依次进入 **Settings → Models**。根据你要使用的服务商，新建或编辑一个模型配置；不同版本的字段名称可能略有不同，但核心只看这四项：

| 需要确认的项 | 你要检查什么 |
| --- | --- |
| 提供商 / 接口类型 | 选择你实际拥有凭据的服务商；使用兼容接口时再填写自定义端点 |
| 模型名称 | 与服务商控制台或官方文档中的可用模型名称一致 |
| API Key | 只填写在本机设置页，不发送到会话、不写进 Markdown、更不要提交 Git |
| 保存结果 | 保存后回到会话页测试；官方指南说明模型设置保存后无需重启工作台 |

保存后，先不要让它读目录或改文件。在新会话输入这一句：

```text
只回答“模型连接已验证”。不要读取工作区，不要调用工具，不要执行命令。
```

**本步完成标准：**能得到正常文本回复，而不是鉴权、模型不存在或网络错误。若失败，回到 Models 检查 Key、模型名、服务商配置或兼容接口地址；不要通过把 Key 发到聊天框里“试一试”来排错。

## STEP 04｜添加工作区，再做第一次只读任务（4 分钟）

回到侧边栏的工作区入口，选择“添加工作区”或同类操作，选中刚才创建的：

```text
D:\dsh-playground
```

添加后确认页面当前工作区显示的是这个路径；官方指南要求先选择工作区，才可使用会话输入区。然后把下面整段任务卡复制到会话：

```text
只处理当前工作区 D:\dsh-playground。

先用一句话说明你的检查计划；随后只读取目录和文件内容，输出：
1. 当前有哪些文件和文件夹；
2. README.md 与 docs/todo.md 分别写了什么；
3. 下一步可以做什么，但不要实际执行。

限制：不要创建、修改、删除文件；不要执行联网、安装或命令操作。
如果你需要调用任何工具，先展示计划，等待我确认。
```

**本步不要只看“它回答得像不像”。**请按下面三项验收：

1. 它只提到 `D:\dsh-playground`，没有把范围扩展到其他目录；
2. 它没有申请写入、删除、安装、下载或批量修改；
3. 它能区分“文件中已经写着什么”和“它建议下一步做什么”。

如果它的计划超出范围，直接拒绝本次动作，再把任务缩短；不要抱着“应该没事”点击允许。

## STEP 05｜第二次才写入：只创建一个可删除文件（4 分钟）

只读任务通过后，在同一工作区发送下面这段：

```text
只在当前工作区执行。

先展示：
- 准备创建的相对路径；
- 文件将包含的三条要点；
- 是否还会执行其他动作。

等待我确认后，只创建 notes/first-task.md。
文件中写入：练习目标、刚才完成的只读检查、我怎样验证结果。
禁止修改 README.md、docs/todo.md 或其他文件；禁止删除、联网、安装依赖和执行批量命令。
```

当页面出现计划或审批卡片时，先核对这四件事：

![Agent 审批前的四个检查问题（原创信息图）](assets/figures/17-DeepSeek Harness 新手教程：别急着让 AI 改代码，先把第一个 Agent 任务跑起来-正文插图02.png)

- 路径是否准确是 `notes/first-task.md`；
- 动作是否只有“创建一个文件”；
- 计划中是否没有下载、安装、删除、联网或额外修改；
- 写错后是否可以直接删除这一个练习文件。

四项都符合，才允许继续。随后回到 PowerShell 手动验证：

```powershell
Get-ChildItem -Recurse -File
Get-Content -LiteralPath .\notes\first-task.md
```

**本步完成标准：**新增的只有 `notes\first-task.md`；原来的 `README.md` 和 `docs\todo.md` 仍在；文件内容能对应你的任务要求。若没有通过，不要让 Agent “顺手修一下全部问题”，先删除或保留这个练习文件，再重新发一个范围更小的任务。

## STEP 06｜把练习迁移到真实项目之前，先做这两个检查（1 分钟）

只有前五步都顺利完成，才考虑打开真实代码仓库。进入真实项目后，先执行：

```powershell
git status --short
git branch --show-current
```

第一条让你知道开始前已有多少本地修改；第二条让你知道自己在哪个分支。第一次在真实项目中给 Agent 的任务，仍然应该是**只读任务**，例如“说明目录结构、找出入口文件、列出可能相关的三个文件，但不要修改”。

涉及删除、批量替换、依赖安装、联网、密钥、线上环境或跨目录访问时，一律改成两段式：**先让它解释计划和影响范围，再由你决定是否批准。**

## STEP 07｜卡住时按现象处理，不要盲目重试

| 你看到的情况 | 先做什么 | 先不要做什么 |
| --- | --- | --- |
| `node -v` 或 `npm -v` 无法执行 | 先安装或修复 Node.js，再重新打开终端验证 | 不要跳过环境检查直接复制启动命令 |
| 页面打不开 | 回到启动终端看第一条报错，并确认浏览器地址是 `127.0.0.1:3080` | 不要反复开多个 `dsh web` 进程 |
| 模型没有回复 | 回到 Settings → Models，检查 Key、模型名、服务商或兼容端点 | 不要把 Key 粘进聊天消息或截图求助 |
| 会话输入区不可用 | 确认已添加并选中 `D:\dsh-playground` | 不要直接把真实项目设成工作区 |
| Agent 的计划超出预期 | 拒绝动作，要求它用更小范围重新说明计划 | 不要因为“看起来专业”就直接放行 |

## 你现在可以立刻做什么

重新打开 PowerShell，从 **STEP 01** 的第一条命令开始。不要跳到写入任务，也不需要一次学会 CLI、插件或无人值守任务。

你真正完成入门的标志不是“AI 帮你写了多少代码”，而是：你知道它正在处理哪个目录、准备执行什么、何时该批准，以及怎样亲手确认结果没有越界。
