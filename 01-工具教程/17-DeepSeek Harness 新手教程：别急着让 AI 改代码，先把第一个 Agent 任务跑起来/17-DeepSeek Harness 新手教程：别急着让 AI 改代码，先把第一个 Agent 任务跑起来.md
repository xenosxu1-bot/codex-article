第一次打开 DeepSeek Harness，很容易犯一个错误：把真实项目拖进去，然后对 AI 说“帮我把这个需求做完”。

先别急。对第一次接触 Agent 的人来说，更重要的不是它能做多少事，而是你能不能看清：**它正在处理哪个目录、准备执行什么、什么时候该暂停。**

本文不要求你学会所有命令。只要在一个空白练习目录里，完成“启动 → 配置模型 → 读取文件 → 审批一次最小写入”这条链路。全程不碰真实代码、不贴真实 Key、不做不可逆操作。

## 第一部分｜DeepSeek Harness 是什么：它为什么不只是一个聊天窗口

DeepSeek Harness 是 DeepSeek 开源的开发者预览项目。它不是一个新的大模型，也不是“输入一句话就自动改完整个项目”的魔法工具；你可以把它理解为一层 Agent 工作台：**把模型、你的工作区和可执行动作连接起来，再让你决定哪些动作可以继续。**

对新手最有用的不是先研究插件或无人值守任务，而是先认识下面三件事：

| 你会看到的部分 | 它解决什么问题 | 第一次使用时怎么做 |
| --- | --- | --- |
| 模型设置 | 让工作台知道用哪个模型、哪组凭据 | 只在本机设置页填写 Key，先测试一句纯文本回复 |
| 工作区 | 规定 Agent 可以查看和操作的目录范围 | 第一次只添加 `D:\dsh-playground` 这样的空练习目录 |
| 计划与审批 | 在读文件、写文件、运行命令前给你一个判断机会 | 先看路径、动作和影响范围，再决定是否允许 |

![DeepSeek Harness 官方中文文档操作路径图（编辑重绘）](assets/figures/17-DeepSeek Harness 新手教程：别急着让 AI 改代码，先把第一个 Agent 任务跑起来-官方中文指南操作路径图.png)

> 图中内容依据官方中文《使用 Web UI》指南整理并重新绘制，**不是官方 Web UI 截图**。官方指南的核心顺序是：启动 Web UI → 设置 → 模型 → 选择工作区 → 发送任务并按当前权限策略处理审批。

这也解释了一个常见现象：页面里的会话输入区不能用，未必是故障，可能只是还没有选中工作区。把 Agent 当成“有权限边界的执行者”，而不是普通聊天框，后面的操作会稳很多。

**适合先拿它做什么：**读项目结构、解释文件、列出计划、在练习目录创建一个可删除的小文件。
**暂时不要拿它做什么：**直接操作客户资料、批量替换、安装未知依赖、删文件、触碰密钥或线上环境。

## 第二部分｜新手 10 分钟跑通第一个任务

![DeepSeek Harness 第一次使用的四步安全闭环（原创信息图）](assets/figures/17-DeepSeek Harness 新手教程：别急着让 AI 改代码，先把第一个 Agent 任务跑起来-正文插图01.png)

> 这张练习路线图只服务于第一次上手：先把每一步跑通，再进入下一步。不要跳过只读验证，直接让 Agent 修改真实项目。

### 1. 准备一个独立练习目录

打开 **PowerShell**，先确认 Node.js 与 npm 可用：

```powershell
node -v
npm -v
```

两行都能返回版本号后，再创建练习目录和两个测试文件：

```powershell
mkdir D:\dsh-playground -Force
Set-Location D:\dsh-playground
New-Item -ItemType Directory -Force -Path .\docs, .\notes
Set-Content -LiteralPath .\README.md -Encoding utf8 -Value '# DeepSeek Harness 练习项目', '', '目标：只在这个目录练习 Agent 的读取、计划与最小写入。'
Set-Content -LiteralPath .\docs\todo.md -Encoding utf8 -Value '待办：整理 README，先不要修改任何文件。'
Get-ChildItem -Recurse -File
```

**完成标准：**你能看到 `README.md`、`docs\todo.md` 和空的 `notes` 文件夹。看不到时先执行 `Get-Location`，确认自己仍在 `D:\dsh-playground`。

### 2. 启动工作台，先只验证模型能回复

仍在同一个 PowerShell 窗口执行：

```powershell
npx @deepseek-ai/dsh web
```

保持终端不要关闭。首次运行可能需要下载和初始化；服务启动后，在浏览器打开：

```text
http://127.0.0.1:3080
```

进入 **设置 → 模型**，按你实际拥有的服务商凭据完成配置。字段名称可能随预览版本变化，但只核对四件事：提供商或接口类型、模型名称、API Key、保存结果。Key 只填写在本机设置页，不发进会话、不写进 Markdown、更不要提交 Git。

保存后先在新会话输入：

```text
只回答“模型连接已验证”。不要读取工作区，不要调用工具，不要执行命令。
```

**完成标准：**得到一条正常文本回复。若失败，回到模型设置检查 Key、模型名、服务商或兼容接口地址；不要为了排错把 Key 粘到聊天框或截图里。

### 3. 选择工作区，完成第一次只读任务

在侧边栏选择“添加工作区”或同类入口，添加并选中：

```text
D:\dsh-playground
```

然后复制下面的任务卡：

```text
只处理当前工作区 D:\dsh-playground。

先用一句话说明你的检查计划；随后只读取目录和文件内容，输出：
1. 当前有哪些文件和文件夹；
2. README.md 与 docs/todo.md 分别写了什么；
3. 下一步可以做什么，但不要实际执行。

限制：不要创建、修改、删除文件；不要执行联网、安装或命令操作。
如果你需要调用任何工具，先展示计划，等待我确认。
```

这一步别只看“回答像不像”。请检查它是否只提到 `D:\dsh-playground`、没有申请写入或下载、能区分“文件已有内容”和“下一步建议”。只读任务越过范围，就拒绝这次动作，把任务再缩小。

### 4. 第二次才写入：只创建一个可删除文件

只读任务通过后，再发送：

```text
只在当前工作区执行。

先展示：准备创建的相对路径、文件将包含的三条要点、是否还会执行其他动作。
等待我确认后，只创建 notes/first-task.md。
文件中写入：练习目标、刚才完成的只读检查、我怎样验证结果。
禁止修改 README.md、docs/todo.md 或其他文件；禁止删除、联网、安装依赖和执行批量命令。
```

出现计划或审批卡片时，逐项核对：

![Agent 审批前的四个检查问题（原创信息图）](assets/figures/17-DeepSeek Harness 新手教程：别急着让 AI 改代码，先把第一个 Agent 任务跑起来-正文插图02.png)

- 路径是否准确是 `notes/first-task.md`；
- 动作是否只有创建一个文件；
- 是否没有下载、安装、删除、联网或额外修改；
- 写错后是否可以直接删除这一个练习文件。

四项都符合才允许继续。随后回到 PowerShell 手动验证：

```powershell
Get-ChildItem -Recurse -File
Get-Content -LiteralPath .\notes\first-task.md
```

**完成标准：**新增的只有 `notes\first-task.md`；原来的两个测试文件仍在；内容能对应你的任务要求。

## 第三部分｜实际操作中最常用的设置与重要功能

跑通上面的练习后，日常最常碰到的不是“提示词技巧”，而是下面这些设置与功能边界：

| 高频项 | 你需要确认什么 | 新手建议 |
| --- | --- | --- |
| 模型与提供商 | 模型名、API Key、服务商或自定义兼容端点是否匹配 | 先用一个能稳定回复的模型验证连接；失败优先回设置页排查 |
| 工作区 | 当前选中的路径是否就是你要处理的目录 | 一个任务只选一个目录；真实仓库首次只做只读任务 |
| 会话任务 | 任务是否写清“要做什么、不做什么、输出什么” | 先要求计划，再要求操作；不要用“帮我全部处理” |
| 审批 | 计划中的路径、命令、写入和联网是否超范围 | 删除、批量修改、安装依赖、跨目录访问一律停下来复核 |
| 本地凭据 | Key 是否只留在本机配置中 | 不要把 Key 写进文章、提示词、代码仓库或问题截图 |

从能力上看，DeepSeek Harness 可以帮助你读取和编辑工作区文件、运行命令、维护计划，并在需要时委派任务；但“可以”不等于“应该立刻授权”。推荐按这个升级顺序使用：**读目录 → 读文件 → 输出计划 → 创建一个练习文件 → 真实项目只读 → 小范围可回滚修改。**

把练习迁移到真实仓库前，先在仓库目录执行：

```powershell
git status --short
git branch --show-current
```

第一条让你知道开始前已有多少本地修改，第二条让你知道当前分支。第一次在真实项目中给 Agent 的任务仍应是“说明目录结构、找出入口文件、列出可能相关的三个文件，但不要修改”。

遇到问题时，不要盲目多开几个进程：

| 现象 | 先做什么 | 不要做什么 |
| --- | --- | --- |
| 页面打不开 | 回到启动终端看第一条报错，确认地址为 `127.0.0.1:3080` | 反复启动多个 `dsh web` 进程 |
| 模型没有回复 | 在设置 → 模型检查 Key、模型名、服务商或兼容端点 | 把 Key 粘进聊天消息“测试” |
| 输入区不可用 | 确认已添加并选中 `D:\dsh-playground` | 直接把真实项目设为第一次工作区 |
| 计划超出预期 | 拒绝动作，要求它缩小范围重写计划 | 因为“看起来专业”就放行 |

你现在可以做的下一步很简单：重新打开 PowerShell，从创建 `D:\dsh-playground` 开始。真正完成入门的标志，不是“AI 帮你写了多少代码”，而是你知道它在哪个目录工作、它要做什么、何时该批准，以及怎样亲手确认结果没有越界。
